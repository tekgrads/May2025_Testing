Diff ways to store data and objects in a program

		
		  1. by using variable 				
                  2. by using class object			
		  3. by using array object			
		  4. by using collection object			 
		
		1. variable problem :
			It can store only one value or one object
		
			if we try to store new values or new object, old values and old objects are lost

		2. class object problem
			it can store only one particular object values
			if we store new object's values, old object values are lost	
								
		3. array problems  
			1. it can store only one type of values or objects
			2. it can store only fixed size values or objects
			3. it doesn't provide inbuilt methods to perform different operations. There is not inbuilt method 
                          for either searching, sorting, removing, inserting
			  elements in an array. To perform these operation, we must 
			  write code explicitly.
			4. it can not store objects in different format
			5. it can not store objects in different order
								
 Solution:-
 ===========        
	The solution for storing multiple values and objects without 'type and size' limitations and to store them in different formats and orders we must use collection
								
 When we need to store one value or one object, we must create a variable

When we need to store multiple values and objects of same and different type of a particular real world object, we must use class object
		   
When we need to store fixed number of multiple values or objects of same type,
 we must use array object
		   
When we need to growable number of multiple values and objects of same type or
different type in different format and in different orders, we must use  collection object.  


Collection:-
===========
 If we want to represent a group of individual obj as a single entity then we should go for collection

Collection framework:-
======================
It defines several classes and interfaces which can be used by collection

9 key interfaces of collection framework:-
=========================================

1. Collection:-
 ==============
       It defines the most common methods which are applicable for any collection object. It is root interface.

Diff b/w Collection and Collections:-
===================================
Collection:- It is an interface which is used to represent a group of individual objects.

Collections:- It is an utility class present in java. util package to define several utility methods like sorting, searching for collection objects

List :-

ArrayList :-
============
 Underlying data structure  is resizable array or growable array.
 Duplicates are allowed and insertion order is preserved.
 Heterogeneous obj are allowed 
 Null insertion is possible

Arraylist and vector implements RandomAccess interface  so that we can access any random elt with same speed.
RandomAccess is a marker interface. ArrayList is best if frequent operation is retrieval and worst if frequent operation is insertion or deletion in the middle.

LinkedList:-
============
Underlying DS is doubly Linked List
Insertion order is preserved
Duplicates are allowed
Heterogeneous obj are allowed 
Null insertion is possible
It implements Serializable and cloneable but not random access
It is best if frequent operation is insertion or deletion in the middle and worst choice if our frequent operation is retrieval


Vector:-
=======
 Underlying data structure  is resizable array or growable array.
 Duplicates are allowed and insertion order is preserved.
 Heterogeneous obj are allowed 
 Null insertion is possible
 It implements Serializable and cloneable and random access
 Most methods are synchronized so thread safe

It is child class of vector.
It is specially designed for Last In First Out Order (LIFO)

methods:-
=========

pop() :- it remove and returns top of stack

peak() :- return top elt of stack without removal obj.'
search() :- if specifies obj is available returns its offset from top of stack
            if not available returns -1


Cursors:-
==========
 There are 3 cursors available to retrieve elts one by one from collection
       1. Enumeration
       2. Iterator
       3. ListIterator


Enumeration:-
=============
We can use this to get objs one by one from collection objs

Limitations:-
=============
Can be applied for legacy classes, hence not a universal cursor
we can get only read access and cannot perform remove operations

Iterator:-
==========
We can apply to all collection obj , hence it  is a universal cursor.
By using iterator we can perform both read and remove operations.

Limitations:-
============
By using enumeration and iterator we can move only towards forward direction , we cannot move in backward direction 

By using iterator we can perform only read and remove operation, cannot perform replacement of new objects

List Iterator:-
==============
By using this we can move either forward or backward direction. hence it is bidirectional cursor
In addition to read and remove we can perform replacement and addition of new objects

IdentityHashMap:-
================

It is exactly same as HashMap only diff is HashMap uses .equals operator to identify duplicates IdentityHashMap uses == operator

WeakHashMap:-
============
It is exactly same as HashMap. In HashMap though the obj does not have any reference then also it is not eligible for GC
If it is WeakHashMap if obj does not have reference then it is eligible for GC

Queue:-
=======
    It is a single ended queue
     Used for storing and retrieving objects in FIFO at begin one ended
     It supports only FIFO order
     
  Deque:-
===========
    It is a Double Ended queue
     Used for storing and retrieving objects at begin and end
     Hence it supports both FIFO and LIFO orders
     
   Queue has only one implementation class 
   	1. PriorityQueue
   
   Deque has only one implementation class 
   	1. ArrayDeque

 1. PriorityQueue -> for retrieving objects in FIFO order in the given priority

 2. ArrayDeque  -> for retrieving object either in FIFO or in LIFO

  FIFO order supporting methods
 			1. add()  or offer()
 			2. poll() or remove()
 			3. peek() or element()
 
 LIFO order supporting methods
 			1. push()  
 			2. pop() or poll() or remove()
 			3. peek() or element()
